---
title: 从反馈中学习
---

通过 `POST /v1/feedback` 或 MCP `feedback` 提交的记忆反馈会保存为事件。**评分层**根据当前所有者的反馈调整记忆排序，但不会修改任何模型。无论使用托管重排器、本地重排器，还是不使用重排器，它都能工作。该功能默认关闭。

```bash
ONTYRA_RECALL__ENGINE=fusion
ONTYRA_LEARNING__ENABLED=true
```

## 它做什么

评分层会进行两类有上限的调整，并根据当前仍然有效的反馈重新计算。计算结果不会单独保存，因此撤回反馈或反馈过期后，下一次结果会随之变化：

- 单条记忆的先验分数：反馈先按来源可信度加权，再按 `HALF_LIFE_DAYS` 的周期衰减到一半，最后压缩到 `MAX_PRIOR` 以内。经常被标记为无关的记忆会逐渐降低排名，经常被采用的记忆则会提高排名。
- 各检索通道的混合权重：系统使用调取追踪中保存的词法、稠密、概念、重排器和决策模型分数，拟合“这条记忆是否相关”。调整后的排序与原始排序之间不会超过 `MAX_SHIFT`，混合权重会随反馈数量增加，但不超过 `MAX_MIX`。任何单一反馈来源的权重都不能超过 `SOURCE_CAP`。

只有你自己的反馈会改变你自己的排序；其他所有者的反馈绝不会。

## 反馈从哪里来

智能体通过 `feedback` 工具提交记忆、查询和对应的 `recall trace`。当某条记忆明显有帮助或产生误导时，插件会提醒智能体在当前轮次提交反馈，不需要额外对话。你也可以在控制台中点击“有帮助 / 无关 / 过时 / 错误”。这些反馈会与当次调取结果关联。没有追踪信息的反馈仍会影响单条记忆的先验分数，但不能用于拟合通道混合权重；摘要中用 `with_features` 统计可用于拟合的反馈。

## 金丝雀

被评价过的召回中有固定的一部分（`CANARY_FRACTION`，由追踪 id 的哈希选出）从不用于训练。每次重新拟合之后，分数层对它们的排序必须至少与原始排序一样好，否则它保持关闭（`reverted`）。在反馈足够之前（`MIN_EXAMPLES` 个被评价的候选，以及 `CANARY_MIN_GROUPS` 次金丝雀召回），它处于 `learning` 状态，不改变任何东西。

由于金丝雀样本来自同一批反馈，它能发现噪声和分布漂移，但无法识别持续且一致的恶意评价。因此仍需要人工审阅样例。后续还计划为重新训练加入独立的可信评估集。

## 审阅样例

反馈质量取决于评价本身是否可靠。控制台的 **Feedback** 页面和 `GET /v1/feedback/outliers`（MCP `feedback_outliers`，位于 `full` 工具档）会按疑似错误或恶意反馈的可能性排列当前有效样例：

- 不一致（disagrees）：评价与召回该记忆时排序所相信的相反（重排器的概率，没有重排器时是最终分数）；
- 翻转（flipped）：同一条记忆和查询被两种方式都评价过；
- 他人不一致（others disagree）：其他所有者对同一条共享记忆作出了相反的评价（管理员视角，`everyone=true`）；
- 突发（burst）：一个来源在几分钟内发送了大量评价。

**否决**（`POST /v1/feedback/{id}/veto`，可附理由；你自己的事件，管理员则可以否决任何人的）会把一个样例永久移出学习：分数层会在没有它的情况下重新计算，任何训练都不会使用它，同一来源再次发送相同的评价也会被排除在外。`unveto` 把它放回来。**管理员可以隔离**一个来源（一个行为者）或整个所有者（`POST /v1/feedback/exclusions`）：在解除之前，它们发送的一切都不会在任何地方计入。**退出（opt-out）**（`POST /v1/feedback/opt-out`）是你自己的选择：你的文本和评价绝不会进入训练池（训练会把各用户的记忆文本汇集到一个模型中，所以这在共享的守护进程上很重要），而你自己的分数层只改变你自己的排序，仍会从它们中学习。审阅需要人类凭据。

## 重新训练重排器 {/* #retraining-the-reranker */}

使用重排器 worker（`ONTYRA_RERANK__PROVIDER=worker`）时，人类可以根据反馈重新训练它（`POST /v1/reranker/train`；`GET /v1/reranker` 显示版本、可用的反馈和过去的运行）。它始终是显式的，并且始终从基础模型开始，所以被否决、已过期和已删除的样例是真正消失了。worker 在主干和单 logit 头上训练一个 LoRA 适配器；期间它回答“busy”，召回在它恢复之前使用自己的原始排序。

训练数据由以下策略明确控制：

- `ONTYRA_RERANK__POOL`：`own`（默认）只用调用方自己的反馈训练，`all` 用所有人的，这适用于一个信任域，而不适用于共用一个守护进程的陌生人。被否决、被隔离和已退出的样例从不参与训练。
- `ONTYRA_RERANK__TRAIN_SOURCES`：`all`（智能体的评价按其较低的信任度计入；同一条记忆和查询若有人类评价过，则以人类的评价为准）或 `human`。
- `ONTYRA_RERANK__SOURCE_CAP`：没有任何来源可以占到超过这个份额的训练权重。
- `ONTYRA_RERANK__ANCHOR_RATIO`：每一个反馈对，都会混入来自随附基准世界的、干净且带标注的对，因此一个很小或有噪声的池不会让模型忘掉它原来知道的东西。

新版本**不会因训练而被激活**。worker 用旧版本和新版本分别给一个可信集（基准中留出的请求）打分，只有当新版本在平均倒数排名和成对准确率两方面都不比旧版本差超过 `ONTYRA_RERANK__GATE_TOLERANCE` 时，守护进程才会激活它。一个被投毒以迎合自身的池，能通过它自己留出的对的验证，但过不了这一关。每次运行都会被记录（`reranker_run`，附有这道关卡的数字）；被拒绝的版本保留在 worker 的磁盘上，任何版本都可以再次被激活。

## 实时调整分类头

在两次重新训练之间，worker 的单 logit 头可以小步跟随反馈（`ONTYRA_RERANK__LIVE=true`；它需要 `ONTYRA_RERANK__POOL=all`，因为这个头是被所有用户共享的：针对每位所有者的学习是上文的分数层）。它被设计成可以撤销：

- 每次都重新计算，不做增量累积。分类头以当前版本为基础，并根据仍然有效的样例从零拟合调整量。因此，否决、撤回或隔离某个样例后，只需重新拟合，不需要从已有参数中反向扣除影响。
- 有界限。该编辑最多只能是头自身范数的 `ONTYRA_RERANK__LIVE_MAX_DISTANCE`（默认 25%），并被拉向零。主干从不被触动，所以被评价文本的隐藏状态只计算一次，重新拟合只需要几分之一秒。
- 有关卡。每次拟合之后，会用带编辑和不带编辑的头分别给可信的基准请求打分；如果带编辑的排序比 `GATE_TOLERANCE` 允许的更差，就不应用它（`reverted`），头保持未编辑状态。
- 批量且显式。反馈的变化会安排一次重新拟合，最多每 `LIVE_EVERY_SECONDS`（默认 5 分钟）一次，前提是已有 `LIVE_MIN_EXAMPLES` 个两类都有的可用对；低于这个数，编辑就被移除。`POST /v1/reranker/live` 立即重新拟合，`POST /v1/reranker/live/reset` 丢弃编辑，`GET /v1/reranker` 显示其距离，以及反馈此后是否发生了变化。
- 被重新训练所取代。重新训练从基础模型开始，其新版本没有编辑。

## 查看它

`GET /v1/feedback/layer` 说明这一层为你做了什么：它的状态（`off`、`learning`、`active`、`reverted`）、原因、它学习了多少样例和召回、金丝雀在有这一层和没有这一层时的准确率，以及拟合出的系数。召回追踪在每个候选的 `final` 旁边保留 `base`（分数层之前的分数）。设置见：[配置](../reference/configuration.md)。
