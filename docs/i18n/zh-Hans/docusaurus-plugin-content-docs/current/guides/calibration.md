---
title: 校准阈值
---

有几项设置是数字，其合适的取值取决于产生分数的模型：召回在其以下保持沉默的余弦阈值、候选必须多接近最佳结果、重复扫描所用的余弦值。换一个嵌入器就需要不同的值。`ontyra calibrate` 会给出建议（融合权重、`abstain_cosine`，以及 `concept_boost`：请求中提到的某个概念，会给与之相关的记忆增加多少分数；除非基准测试显示有增益，否则保持为 0）。

```bash
ontyra calibrate            # 列出将要向嵌入器发出的请求，然后停止
ontyra calibrate --yes --out calibration.json
ontyra calibrate --from calibration.json      # 重新读取已保存的一次运行：不调用模型
```

它会在一个临时存储中，用**你配置的嵌入器**运行 Ontyra 自带的一套带标注的基准（一个虚构人物的记忆、几百条带有正确答案的请求，以及被标为重复、更新或不同的陈述对），然后离线搜索这些设置。它会先打印嵌入请求的数量，并且在没有 `--yes` 的情况下不会调用非 `hash` 的嵌入器，因为托管模型可能会计费（大约一千条短文本；本地模型需要几分钟）。已部署的数据库绝不会被触及：临时存储位于内存中，或是同一个 SurrealDB 服务器上、位于独立命名空间的一次性数据库。

输出是一组环境变量，以及它的依据：

- 你**当前**的设置和**建议**设置，在用于搜索的那部分基准（`tune`）和留出的那部分（`holdout`）上的通过率；
- 模型究竟能多好地区分相关与无关的记忆；做不到的模型会被明确告知，而不是得到一个阈值；
- 这个建议是处在一片同样好的设置的平台中间，还是处于刀锋边缘。

把这些值应用到守护进程的环境中并重启。它们确定的是模型的**分数尺度**（相关与无关的余弦值分别落在哪里），而不是你的领域：基准世界是虚构的。

## 决策模型与重排器

当配置了决策模型（`ONTYRA_DECISION__*`）或重排器（`ONTYRA_RERANK__*`）时，同一次运行还会就基准的请求和陈述对询问它，并报告：

- 决策模型的 `decision_weight` 和 `decision_margin`，重排器的 `rerank_weight`（以及与之搭配使用的余量）：**不使用**该模型、使用你当前的值、使用建议的值时的通过率。如果模型没有在原有排序之上带来改进，输出会这样说；
- 重复扫描的 `confirm`：在该分数下，模型所接受的内容中至多 5% 不是真正的重复。

成本会先列出（每条基准请求一次决策请求，每个陈述对两次），并且必须加 `--yes`，因为这些模型也可能计费。运行结果还会打印 `ONTYRA_RECALL__CALIBRATED_FOR=<embedder>`；设置它之后，当嵌入器日后改变、阈值不再适用时，控制台的总览会告诉你。

## 检查你自己的存储

```bash
ontyra calibrate --own            # 需要 ONTYRA_RECALL__ENGINE=fusion
```

基准确定的是模型的尺度；你的数据可能处在别处。这项只读检查会用你自己约六十条记忆的开头几个词去查询你配置的数据库（*切题*：记忆本身应当排第一），也用基准中无关的请求去查询（*离题*），并报告你的 `abstain_cosine` 落在这两种分布之间的什么位置。它不需要标注，只需要嵌入器，也不写入任何东西：不留追踪，不记使用。切题探测比真实请求容易，所以用它来发现明显不适合你数据的阈值，而不是用来微调阈值。

## 召回记录了什么

使用 fusion 引擎时，每条召回追踪都会保留最佳候选各通道的分数（余弦、BM25、词法、稠密、融合、重排器和决策模型的概率，以及每个候选是否被展示），数量为 `ONTYRA_RECALL__TRACE_CANDIDATES` 条（0 表示关闭）。引用该追踪的反馈随后就有了它所需的特征：`GET /v1/feedback/summary` 把它们计为 `with_features`。早于 `ONTYRA_RECALL__TRACE_RETENTION_DAYS`（默认 180）的追踪会被删除，除非有反馈事件引用了它。[分数层](./feedback-learning.md)从这些反馈中学习；用它们来调节阈值本身，尚未实现。
