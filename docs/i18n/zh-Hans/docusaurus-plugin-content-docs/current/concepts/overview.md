## 记忆的种类 {/* #memory-kinds */}

每条记忆都有明确的种类和相应字段，因此规则、事实和观察不会混在一起。

| 种类 | 它保存什么 |
|---|---|
| `fact` | 关于某个主体的陈述（`subject`、`predicate`、`object`） |
| `directive` | 一条规则：`strength`（`must`、`should`、`prefer`）、`polarity`（`do`、`avoid`）、`rule`、`rationale` |
| `decision` | 选了什么、有哪些备选，以及为什么 |
| `event` | 发生过的事，带时间和结果；其相关性会衰减 |
| `procedure` | 某个触发条件出现时要遵循的步骤 |
| `task` | 要做的事，带截止日期和状态 |
| `lesson` | 一种情境、从中得到的洞见，以及应当怎么做 |

所有种类还都带有 `text`（可读的陈述）、`confidence`、可选的过期时间，以及它们在何处、何时适用（见下文）。

## 提案与审核

智能体不能直接改写记忆，只能提交由一组操作（`add`、`revise`、`supersede`、`retract`、`link`、`annotate`）组成的**变更提案**。Ontyra 会检查字段类型、目标记忆和引文来源，再由**策略**决定直接提交、留待审核或拒绝。待审核的提案可以在运维控制台或通过 API 处理。详见[审核与策略](../guides/review.md)。

已经保存的修订不会被改写。纠正一条记忆会生成新修订；替换记忆时，旧版本会标记为已被取代。完整历史始终可以查询。

## 记忆适用于哪里

- 锚点把记忆绑定到一个地点：例如 `file://host/path/to/repo`、`ssh://user@host` 这样的 URI，或某个仓库。一个路径可以覆盖其下的一切（`subtree`），也可以只覆盖它自身（`exact`）。
- 作用域：`universal` 记忆处处适用，并且总会出现在会话简报中。默认的 `contextual` 记忆只有在当前情境与它有关时才会交给智能体，例如锚点匹配、限定条件成立，或当前工作涉及相关概念。既不是 `universal`、又没有关联任何对象的规则没有明确作用域，写入时 Ontyra 会发出警告。`topical` 用于某个模块或项目的主题知识；只有当前工作涉及该主题时才会提供给智能体，不会仅因文本相似就出现。它必须通过 `about` 指明主题。`reference` 则只作为参考资料保存，不会出现在调取结果、简报或检查中，需要使用 `consult`（或 `search`）查询。引用外部来源的记忆默认为 `reference`。通常还会保存一条简短的 `topical` 概览，提醒智能体某个主题有资料可查。
- 限定条件是各种条件（“仅当 python 为 3.12 或更新版本时”），可以是必要条件、充分条件、前置条件、排除条件或触发条件。

## 本体

概念（`python`、`docker`、`localai`）以及它们之间的关系（`is_a`、`part_of`、`same_as`、`replaced_by`、`depends_on`、`disjoint_with`），使得关于某事物的记忆可以从相关事物找到，并为条件提供了词汇。智能体提出本体变更（定义、建立关系、添加别名、编辑、拆分、合并、弃用）；除非某个操作被配置为自动批准，否则由人来批准。见[本体](../guides/ontology.md)。

## 如何调取记忆 {/* #recall */}

- 简报：会话开始时，此处适用的完整规则集，加上锚定在此处的事实与决策，以及所有到期的事项。
- 调取：每条消息到来时，系统会寻找与文本和当前情境相关的记忆。词法检索和嵌入检索先找出候选，再按适用性过滤和评分，最后控制在词元预算内。如果没有足够相关的结果，系统不会返回任何内容。
- 检查：在执行有副作用的操作之前，必须先知道的事情。
- **会话记录表**可避免同一条记忆在一次会话中重复出现。如果已经提供过的记忆后来被修订或撤回，系统会发送一次更正。

## 可选的模型服务

Ontyra 只会调用以下可选外部服务：**嵌入模型**、**重排器**和**决策模型**。决策模型负责判断排名靠前的候选中哪些与当前情境有关，只返回概率，不生成文本。这些服务不会修改已保存的内容；连接失败时，Ontyra 会跳过相应步骤。
